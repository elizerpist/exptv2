## 14. Implementation contract

1. **Three settings rows.** Replace the old sharing/tour/setup flow. First show “Android kisegítő lehetőségek”, with actual status for the dedicated Fluvi component, opening `Settings.ACTION_ACCESSIBILITY_SETTINGS`. Refresh on return. Beneath it use mutually exclusive “1×1 ORB” and “2×2 ORB”. New installs default to 1×1. Persist size while disabled. The OS service switch activates/deactivates the feature. Inline status in the first row can signal a pending bind. No fourth control, period, mode, category, financial disclosure dialog, picker or resize UI. Never open a settings Activity from wake, widget click, service connect or drag.
2. **Fixed binding and upgrade.** Preserve the R49 service component `com.fluvi.app/tk.zwander.lockscreenwidgets.services.Accessibility` with the user-facing label “Fluvi zárképernyős ORB”. Bind only `com.fluvi.app.widget.orb.FluviHeaderOrbWidgetProvider`. Persist the pending ID before requesting any grant. Attempt `bindAppWidgetIdIfAllowed`, then if required launch Android's fixed-provider `ACTION_APPWIDGET_BIND` only from resumed, unlocked Fluvi settings. Consume the same ID after one-time or persistent approval, validating OS binding, provider, profile and host ownership. Persist/reconcile across Activity recreation and process death. Cancellation releases only the newly pending owned ID, with no dialog loop. A size-row tap can explicitly retry. Reuse a correct existing active owned ID. On R49 upgrade migrate only this UID's host-1003 frame records, remove superseded owned IDs and discard incompatible packets. Preserve enabled/off/revoked intent. If old access was granted but the feature inactive, keep it dormant until a deliberate settings action. Never enumerate-and-delete external WA, launcher or other-host widget IDs. The active size switch reuses the same ID.
3. **One live Balance source.** Attach one lock material publisher to the shell-owned `DashboardHeaderVisualController` after presentation preferences restore. Reuse the same Balance visual evaluation as the home Balance branch (`balanceFrame`, `DashboardHeaderMaterialSnapshot.capture`, `dashboard_active_header_frame_preparer.dart`). Feed the shared canonical header geometry/DPR measured by the existing header and its last valid values when offstage. Bootstrap after preference restore from the normal Fluvi layout/available display metrics when first enabled from settings. Subscribe to committed Balance tuning, portal settings generation and visual-export commits, including the final slider value. Schedule on enable/reconnect and material changes, including changes with settings on top or Mind/Budget active. A transient live preview may coalesce to the latest visual change, and the final committed setting must publish. Compare semantic material keys independent of tick phase. Use no transaction, account, scope, summary pill, category, dashboard-route visibility, installed home widget, or navigation back to Balance as a prerequisite. Export the same palette, stops, motion state, shader/effect, speed and phase origin as the visual reference. Limit the lockscreen packet to rendered ORB frames and playback/identity metadata. Keep monetary values, text, per-account identifiers and transaction records out of every lockscreen RemoteViews action and content description. Honor reduced/static motion as the reference does.
4. **Continuity and withdrawal.** Fresh initialization prepares a valid Balance packet for local native use before lock whenever the app is active. Use the current bounded frames, payload budget, phase-aware playback and `orbPlaybackViews`. Make `HeaderOrbWidgetContent` and `HeaderOrbPackage` Balance-only. Track pending generation separately from the last good Balance version. Atomically validate, persist and deliver the newest committed complete packet. Retain the last good Balance loop during preparation or a failed replacement, reject late A/B callbacks after C, and retry the latest desired key on the next valid trigger. On disable/revocation, cancel publication, withdraw the window and invalidate private state. Block stale packet resurrection across restart/upgrade. Wake, drag and dashboard navigation do not render new Flutter frames or reset playback. A missing initial packet is reported as pending.
5. **Long-press movement.** Adapt keyboardtest's `LabDragDetector`, `LabDragState`, `LabFrameBounds` and WA frame update pattern. One finger must start on the ORB, hold through the Android long-press timeout within touch slop, then drag. Use raw screen-coordinate delta from the initial pointer and actual applied window origin. Update only the attached root's `WindowManager.LayoutParams.x/y` via `safeUpdateViewLayout` on the main thread. Never offset, pan, translate or resize its child. Convert center-gravity offsets against the same display frame, clamp the entire outer rect within usable bounds accounting for insets/cutouts, and keep circle and root together. Save normalized center once on successful ACTION_UP, verified against applied geometry. Restore on relock/restart. Resize around that center, clamp again and recompute after rotation or density changes. If the selected size cannot fit, suspend until it fits. On ACTION_CANCEL, second finger, failed window update, detach, service loss or unlock cancel the gesture, retain the previous committed position, and respect the current hide state. Short taps and empty space trigger no WA actions.
