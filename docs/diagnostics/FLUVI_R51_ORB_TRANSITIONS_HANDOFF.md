## 14. Implementation contract

1. **Entrance.** Seed the visual wrapper alpha=0, scaleX/Y=.95 before the newly eligible root can flash. After the first valid draw opportunity, animate these properties together to 1 with the WA platform property animator, its default interpolation and 300 ms base duration. Honor Android animator duration scale once. When system animators are disabled, start directly at 1. Use an attachment-owned one-shot pre-draw/draw callback with WA's bounded next-draw semantics (up to 50 ms, an upper bound, never a mandatory wait). A timeout still rechecks the live episode. The fresh-add 50 ms eligibility delay stays separate. Start only on first admission in a genuine wake/lock episode. A reconnect showing an already locked main screen may initialize one fresh admission. Same-wake restore from shade, scans, drag, resize, material updates and frame ticks cannot restart the effect. The decorative entrance and the repeating Balance motion have different clocks. A selected static Balance material may still fade in.
2. **One terminal withdrawal.** Funnel explicit SCREEN_OFF/USER_PRESENT, service loss, primary-display loss/non-ON and freshly observed noninteractive/unlocked states through one main-thread operation. Those explicit negative broadcasts act on receipt without a query. For refresh, place the cheap default-display/interactivity/keyguard gate before geometry, positive tree work, content refresh, the fresh-add delay and filtered early returns while an ORB or an admission is outstanding. Unrelated displays and the exact own overlay cannot grant visibility. Preserve hide-on-loss and reject stale worker results by identity. Recheck before applying a scan and attaching. Reuse fresh readings in the same ingress when possible. An unobservable state cannot authorize a show. A transient missing scene or shade/bouncer is a temporary withdrawal, distinct from a completed power/unlock episode. Keep the existing ordinary MAIN proof for admission. Prioritize a definite restrictive fact already present in the same snapshot. A package name, window focus loss, generic content event, wallpaper color or motion is insufficient proof of unlock.
3. **Race and lifecycle.** First close the matching episode, invalidate its pending scan/add/draw/gesture/animator ownership and block stale re-entry. Disconnect the old animator callbacks before cancel can invoke an end listener. Immediately zero visual alpha and mark the real root INVISIBLE on the same main dispatch, then remove the actual window and release the listener. Move logging, serialization and other expensive cleanup after the visual revoke. No exit fade, animation-end wait, posted debounce or wait on the scan/host. An idempotent second hide cannot revive or replace anything. On remove failure keep the old root invisible, deny new attach while it remains owned and use one bounded cleanup retry on the main loop. Preserve the real result/detach identity. Old cleanup can never affect a successor. After sleep require a credible new wake (new SCREEN_ON or an observed noninteractive/off → interactive/ON edge on the default display) plus current locked, ready, MAIN. After unlock require a new lock episode, with an observed lock transition or new sleep/wake plus fresh locked MAIN. Neutral callbacks alone cannot release either barrier. Initial genuine service connection has its own fresh bootstrap. Ordinary shade/PIN return uses fresh MAIN within an otherwise live episode.
4. **Capture UX.** Add one Android “Zárképernyő” section to the existing onscreen debug panel. Supply exactly two actions. “Felvétel indítása” toggles to “Leállítás” while recording, and “Vágólapra másolás” freezes-and-copies an active recording or recopies the frozen one byte-for-byte. First copy is disabled until a session exists. Show recording/frozen state, elapsed duration, session ID, drops and copy confirmation/error. Service disabled/disconnected must yield an informative valid status. Going to background or hiding/reopening the panel leaves the native session alive. A failed copy preserves the frozen data for retry. Protect against concurrent taps. Normal release/unsupported platforms retain their existing debug exposure. No Android screen recording permission, video capture, ADB or desktop is needed for the owner.
5. **Capture ownership and schema.** Put a small native recorder in the service's process, reachable from the existing Activity engine registration. Expose start/status/stop-and-freeze/get-frozen through a local method channel. Keep it independent of the generic dashboard logs and all deprecated keyguard engines. Version the UTF-8 payload, e.g. `FLUVI_WA_LOCKSCREEN_CAPTURE_V1`. Write build SHA/purpose/version, API/model, route, size, capture/process/service/episode/window/widget IDs, event sequence, scan ID and timestamps. Record state for denied/filtered ingress before discarding it, coalescing repeat event counters. Include event-supplied uptime when valid, callback-received uptime, and elapsedRealtimeNanos with paired uptime/elapsed samples at start/end and each power transition. Set absent external endpoints to UNOBSERVED. Use enumerated, bounded fields for event class/reason/source, default-display state, interactive/locked (including UNKNOWN), last scene, eligibility result, scan offer/start/result/cancel/apply, wake barrier, attach, drawable material ready, entrance begin/first nonzero/end/cancel, programmatic alpha/visibility applied, remove begin/return/error, onDetachedFromWindow, host-stop begin/end and any later reattach or rejected stale callback. Correlate one hide operation across these markers. Frame/draw/property receipts are software observations. Never capture node text, PIN, notification content, account details, arbitrary window titles, screenshots or clipboard contents.
6. **Bounded collection.** Default OFF with a cheap no-op, deduplicate unchanged events and keep a separate reserve for terminal and overflow records. During an explicit capture only, a single off-main, read-only probe samples public interactive/keyguard/display values while an attached ORB is visible, up to once per 32 ms, with at most one call outstanding, 10 s per visible episode and three episodes per capture. Store changes, first/last observations and gaps. Reset the per-episode budget only for a genuine new episode. This probe cannot trigger a production hide/show. Use it to distinguish a late delivered callback from a late public fact. Cap capture at 90 s and final text at 128 KiB including metadata. Report observation/retention/drop counts, truncation and skipped/busy probes. Preallocate records and perform no blocking I/O, binder calls for logging, string formatting or hashing on the withdrawal path. Freeze one immutable snapshot, hash its exact UTF-8 body, export the hash outside the hashed body and retain the last frozen snapshot app-privately across Activity recreation. On process death, reload any fully frozen snapshot and label an interrupted active session explicitly, never silently continue it. No automatic upload or silent clipboard write.
