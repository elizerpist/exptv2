## 8. Current source facts

`WaLockscreenService.onAccessibilityEvent` timestamps ingress, rejects unrelated displays, reads the current state before own/foreign content filtering, then offers a cancellable scene scan. `WaSystemReader` reads display, interactivity and keyguard with short-circuiting unless a complete probe is requested. `withdraw` saves the decision timestamp, calls `hideOrb`, cancels the old scan and emits its terminal record. `WaOrbWindow.hide` revokes owner/entrance, zeros wrapper/root alpha, sets INVISIBLE, cancels work, calls `removeViewImmediate`, then stops listening. The 300 ms animator is enter-only. The frame is an accessibility overlay at the configured position. The service XML requests 50 ms. `WaLockscreenCapture.Session` uses three rings, a 90 s deadline and a passive nominal 32 ms probe for at most the first three visible episodes / 10 s each. Widget 33 is reused over five *different* windows in the handset export. ## 14. Instrumentation contract

1. **Arm before start and restore on exit.** Extend the existing start operation with an explicit arm. On the service main thread read its current service info, remember baseline value and session/generation, change only the timeout via the public serviceInfo setter, read it back, and acknowledge before admitting the measurement. Apply the same command/ack path to both arms. Disabled service, visible window at arm time, unknown baseline, readback mismatch, or externally changed settings produce an explicit invalid/error state. Avoid overwriting unrelated fields on restore. Restore the pre-arm value on stop, copy-to-freeze, expiry and recoverable failures. On unbind/death invalidate outstanding ownership. On fresh service connection read back the ordinary 50 ms XML configuration and explicitly restore that field if the previous interrupted override survived. Verify before authorizing a new arm. Distinguish a pending restoration from a successful readback. Freeze/export cannot depend on Flutter remaining visible. Do not mark an interrupted session as complete. [Public runtime setting](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#notificationTimeout)
2. **Small loss-resistant V2.** Give the first six distinct attached windows per recording a fixed summary slot each. Keep overflow counts and preserve already assigned slots. Track scene/restriction reason when known, first/last active state, a bounded preterminal sample (last confirmed allowed and first confirmed negative with both read start/end; capture/owner crossing flags), earliest callback receipt/public negative, gate decision, local hide, detach, removal return/error, host stop, later attach and the next allowed wake. Record event type, valid event uptime, callback uptime/elapsed, display ID/state, existing event change masks where valid, owner alias and source class (own/SystemUI/home/other/unknown from information already available, no real names exported). Retain informative near-terminal true controls. Respect availability flags; `scene=MAIN` copied from the prior state does not become a fresh scan result. Count accepted/filtered callbacks, scan offer/start/cancel/apply, in-flight work, peak and maximum **observed** probe gaps. Aggregate repeats off the hot path; retain the sequence and native elapsed timestamps of critical transitions separately from lossy detail. Keep a 128 KiB UTF-8 ceiling and body digest; put all allocated summaries ahead of raw details in the byte budget. V1 recopy after app upgrade must remain byte-exact. Use old capture-compatible getters or dual-version parsing. Keep the 90 s maximum, 32 ms passive probe, ≤3 probe episodes × ≤10 s; the independent per-owner summary does not increase probe scope. Any missing sample remains unknown.
3. **Correlated stock timeline.** At the existing callback/decision/local hide/detach points add fixed-name, capture-gated app trace markers with numeric owner/operation correlation, paired uptime/elapsed anchors at transition boundaries and no per-frame tree/IPC/serialization. On the stock fixture collect typed system input, keyguard-going-away / WM Shell transition, power/interactivity, WM, SurfaceFlinger layers/transactions and available present/frame timing. Track the exact Fluvi layer ID from the live ORB window and any transition parent/snapshot until continuous absence or a new admitted window. Begin/end trace and verify sources and lost events. Keep trace-processor/Winscope source names and versions. A window/layer disappearing alone does not prove that the composed pixels disappeared. [Winscope capture](https://source.android.com/docs/core/graphics/winscope/capture/adb)
4. **Independent pixels.** On the synthetic stock device choose a known Balance palette/position distinguishable from wallpaper and launcher, with a separate background region. Prequalify a real frame sequence and decoder on the runner; verify nonempty decoded frames, PTS and known visible→absent calibration before the first trial. Record uninterrupted compositor frames through the transition, with an independently timestamped main-lock/launcher reference. Record AVD video as composed output only. Use a common trace clock when available; otherwise bracket a disposable fixture-generated visual sync edge at the beginning **and end**, outside measured transitions. Retain calibration frame IDs/times, drift, intervals, cadence and worst uncertainty. Without bounded alignment, report frame-only and app-only timing separately. For sleep require independently known locked state and OFF/DOZE, and distinguish a stalled recorder/last encoded frame, black content, AOD and panel power-off. Preflight independent power-state evidence; record a missing frame stream after OFF as unavailable. Do not add a visible mark to the owner's ORB or request screen-capture access.
5. **First divergence.** Export a row for each attempted action including invalid attempts, with app-owned, OS and frame endpoints in separate columns. Record event generation→receipt in uptime, independent negative read end→decision, decision→LOCAL_HIDE, local→detach/return on elapsed, ordered reference transition→last ORB / first sustained absence on calibrated frames. Show the last definitely allowed main-lock frame, first definite forbidden frame, last visible ORB frame, first absent frame and the observation interval. A swipe or power button request has its own timestamp. A valid active owner needs a pre-action painted reference, same-episode ordering, and separation from the next wake. For a continued visual after local hide require a *positively* identified ORB in a sufficiently later matched frame, outside clock uncertainty. Without a uniquely attributable layer use “post-local ORB pixels, owner unknown”. Report upper/lower bounds and gaps. Do not infer a flag-change timestamp from event creation or subtract different devices' clocks.
