## Implementation and limits

The Worker classifies the existing three-slot pool at accepted leases and existing frame opportunities. A coherent, exact-grant, exact-child pressure ticket distinguishes old held uses from current in-flight work; ordinary transient conditions require three distinct opportunities spanning 50 ms, while the all-old-held case can switch immediately. The controller checks the current attached owner and allowed scene and atomically claims the ticket. It retires the exact isolated producer, adopts the current material time into the retained View and resumes the existing shader/clock. The pressure route persists through subsequent attachments until actual receipt plus fence-safe drain makes a future eligible attachment able to return to isolated rendering. No transaction commit, hide, elapsed time, or timeout frees a submitted buffer.

The same source includes attachment-owned bounded `r08*` route, pressure, identity, first-draw and worker evidence in LIGHT/FULL console output. The existing service fixture removes only its redundant post-rapid `wm dismiss-keyguard` and records timestamped public keyguard observations. The independent recovery and strict isolated **functions** catch and report failures separately, so both executed in each declared repetition, but they currently run inside the same host-selected JUnit method: the handoff's separately named JUnit test requirement is **NOT MET**. No runner/CI dependency or deadline was widened to conceal that gap.
