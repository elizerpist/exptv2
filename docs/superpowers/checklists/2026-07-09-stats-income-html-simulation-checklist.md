# Stats Income HTML Simulation Checklist

Source: user request on 2026-07-09: "mutasd meg html-ben... szimulált legyen... előző html alapján".

Reference inputs:
- Current expense/category-scope mockup: `docs/prototypes/stats_fastfood_2025_sim.html`
- New income mockup: `docs/prototypes/stats_income_2025_sim.html`

Approved app implementation baseline for income mode:
- App equals mockup: implement from `docs/prototypes/stats_income_2025_sim.html`, not from memory.
- Reuse the previous FastInfo/header/monthcard visual structure, sizes, font system, magnet strip design, and threshold controls.
- Threshold slider is a transaction amount threshold for the income prototype test, not a monthly-total gate. Default is `300 000 Ft`, range `0..600 000`, step `10 000`.
- Simulated 2025 data must include these visible income patterns:
  - one salary day around `300k`,
  - two income days around `200k` each,
  - many microtransactions totaling around `300k`,
  - weekly income days totaling around the monthly target.
- The latest accepted income prototype needs stronger amount variance for testing: monthly totals should be unique, not 10k-identical threshold values, and split months should have visibly uneven transaction amounts without duplicated generated amounts.
- Main graph is now `Income health · App current` for testing the app's existing income-health math. It uses the same formula as `StatsCategoryScopeSeries._incomeControlData`: monthly total index vs period average, active income day index vs period average, and month-to-month stability index combined as `0.55 total + 0.25 activeDays + 0.20 stability`.
- The main graph is score-only. The accepted secondary function belongs to the lower chart, not the upper chart: `küszöb feletti volumen` shows the threshold-filtered monthly income total as a compact line/area chart. It uses the same dynamic x-axis and normalizes the threshold-filtered monthly total to `0..100` against the visible max.
- The slider acts as a transaction threshold for the HTML prototype: the chart x-axis includes months that have at least one income transaction/day-cell at or above the slider value. `0` includes every month with income; high thresholds can show sparse or empty states.
- Main graph x-axis is dynamic month-based and shows only the current filtered month labels using the same `7.4px` x-axis label design as the expense mockup.
- Header magnet and header value use the current visible score endpoint from the main FastInfo score line, not the older aggregate `_scoreFromIncomeHealth` value. Header value is score only, for example `77/100`.
- Helper graph uses threshold-filtered monthly totals as samples: income above the current transaction threshold contributes to the visible sample series; if threshold is `0`, all income months are visible samples.
- Helper bar height and opacity both follow normalized absolute deviation from the visible sample average through `drawAverageDeviationBars`.
- Monthcards show income day circles only for income day-cells whose amount is at or above the current transaction threshold, so microtransaction months fade out gradually by amount.
- Lower-chart design now uses threshold-visible samples as average-deviation bars. The center line is `0`, meaning the average of the currently visible threshold samples. Bars extend upward for above-average samples and downward for below-average samples. Bar opacity and height both follow absolute deviation from that visible average.
