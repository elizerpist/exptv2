## No-Omission Rules

1. Every user-reported bug gets a stable sequential ID immediately:
   `COMMONSTATS-BUG-001`, `COMMONSTATS-BUG-002`, and so on.
2. The user's source wording must be recorded losslessly in either the main
   table or the intake log. If the wording is shortened in the table, the full
   wording stays in the intake log.
3. Never delete, reorder, merge away, or renumber existing rows.
4. If a report is a duplicate, still add a new row and link it to the earlier
   ID in `Disposition`. Duplicates are not omitted.
5. If the user corrects or supersedes an earlier report, keep the old row and
   mark the relationship in `Disposition`. Corrections are not silent edits.
6. Status values are limited to `NOT DONE`, `PARTIAL`, `BLOCKED`, and `DONE`.
   New bug reports start as `NOT DONE`.
7. After every intake update, report back the new ID, total bug count, and the
   full list of open `NOT DONE` / `PARTIAL` / `BLOCKED` IDs.
8. Before any implementation pass, re-read this full file, state the selected
   IDs, and leave unselected IDs untouched.
9. Before claiming completion, reconcile every selected ID with evidence in the
   `Verification method` column. No selected ID may remain `PARTIAL`,
   `BLOCKED`, or `NOT DONE` unless the user explicitly defers it.
