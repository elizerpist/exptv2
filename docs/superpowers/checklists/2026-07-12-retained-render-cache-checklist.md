# Retained Render And Cache Pipeline Checklist

Date: 2026-07-12

Status note: this is the pre-implementation acceptance checklist. The matching design document is `docs/superpowers/specs/2026-07-12-retained-render-cache-design.md`. Implementation must not be called complete until every row below is `DONE` or the user explicitly approves a deferral.

## Source Inputs

- User request, 2026-07-12: app should initialize once, keep views retained, remove repeated gray loading/spinner screens, preserve the current menu after background/resume, refresh background-changed transactions invisibly, and make home/stats income/expense, summary scope, threshold, snapshot, and bottom-nav switches instant.
- User request, 2026-07-12: include the idea of using GPU/VGA for the stats menu, while validating whether Flutter component rendering is the costly part.
- Perplexity answer pasted by user, 2026-07-12: the bottleneck is probably Dart build/layout/state/aggregation rather than lack of GPU; target retained UI, precomputed models, render-frame cache, prewarm scheduler, lifecycle sync, stale-while-revalidate, CustomPainter/RepaintBoundary only where measurement proves widget/render cost.
- Current code inspection, 2026-07-12:
  - `lib/features/shell/expt_shell.dart` already owns long-lived `TransactionStore`, `StatsPageController`, retained tab page map, `PageView.builder`, `TickerMode`, and resume hooks.
  - `lib/features/transactions/state/transaction_store.dart` already guards `start()`, has home-side caches and `_prewarmCriticalCaches`, but summary changes/reloads still invalidate broad caches.
  - `lib/features/stats/stats_page.dart` owns local stats state, a single-entry `StatsRenderFrameCache`, local worker scheduling, `_snapshotFramePending`, and a spinner-based `stats-frame-pending` surface.
  - `lib/features/stats/data/stats_render_frame.dart` has a single-frame cache keyed by transaction/category object identity plus stats filter/scope/threshold fields.
  - `lib/features/stats/data/stats_render_frame_worker.dart` already builds stats frames off the UI isolate through `Isolate.run`.
  - `lib/features/transactions/transaction_home_page.dart` still renders a full-page spinner while `TransactionStore.loading` is true.
