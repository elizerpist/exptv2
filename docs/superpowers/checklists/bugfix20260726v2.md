## B3M-A3 FastInfo root-cause finding — 2026-07-26

This is a process and source-selection failure, not a request for another
approximate restyle.

1. The current Flutter source claims its visual spec contains the final B3M-A3
   cascade, but it freezes `insightHeight = 104`. The actual standalone B3M-A3
   constructor activates `data-today-redesign-density="time-rail-compact"`, whose
   active CSS sets the FastInfo grid/card height to `72px` and also changes the
   padding, icon, grid and typography measurements. The expected `144028`
   screenshot visibly uses that compact cascade; the Flutter `144006` screen
   does not.
2. The Flutter port duplicates FastInfo/detail measurements throughout widgets
   (`24`, `15`, `36`, `9`, local padding and local text styles), instead of
   consuming one complete active-source metric set. As a result, an outer card
   can look roughly plausible while its internal hierarchy is still from a
   different source state.
3. The existing tests freeze those Flutter values themselves (for example,
   they assert the incorrect `104px` FastInfo height). They prove internal
   consistency, not equivalence to the active B3M-A3 HTML cascade.
4. A visual `DONE` gate was applied without an all-components, same-state
   HTML–Flutter overlay. That allowed a partial change—such as dimension
   pills—to be accepted while the cards' internal layouts remained wrong.
