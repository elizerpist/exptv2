## Root-cause evidence captured before implementation

- **Why the inactive-action test passed:** the prior test compared the local
  `Ink` decoration with the Summary token and never sampled the rendered pixel
  in the production `ThemeSurface` tree. The selected token is translucent
  `0xF0FFFFFF`; over the active surface it resolves visually to white. This is
  a token/compositing and test-host gap, not evidence that the screenshot is
  wrong.
- **Why the SearchPill test passed:** it asserted only the local
  `TextField.decoration.border == InputBorder.none` and an outline widget key.
  It did not exercise the app's effective `InputDecorationTheme` paths or
  compare focused pixels. The screenshot shows the untested inner turquoise
  focused border and a separately drawn pill outline.
- **Why the pencil test passed:** the prior test was written with the reversed
  requirement: it required the right-edge pencil to be absent and did not
  require absence of the name-adjacent pencil. It therefore proved the wrong
  behaviour.
- **Rail trace finding:** rapid rail movement repeatedly creates
  `summary-native-picker`, `recurring-ghosts`, `balance-frame-resolve` and
  inactive Stats-prewarm work. A single frame resolve takes roughly 176–209ms
  in the supplied trace, rail loads take 315–918ms, and duplicate equal-scope
  loads are visible (for example `2021-11`, `2021-08`, `2025-12`). Seven
  prebuilt visual slots do not prebuild or coalesce the underlying query/frame
  work.
- **Scroll-trace limitation:** the reported 221–2002ms
  `balance-log-scroll` duration measures `ScrollStart` to `ScrollEnd`, so it
  includes the user's gesture duration and is not itself a frame-jank metric.
  V3 tracing must separately record input-to-publish, frame resolution,
  mounted-row changes and first-paint timing.
- **FastInfo/detail source mismatch:** the app did not implement the final
  HTML cascade. For example, the HTML's No-spend view label is absolutely
  placed at the bottom-left of the card, while Flutter puts the dimension text
  in `_FastInfoHeader` as a trailing widget, stealing title width and causing
  the visible wrap. More materially, later permanent-scope HTML selectors
  override the generic 208px/36px/15px detail values with 248px cards, 46px
  tiles, 21px principal amounts and 20px option pills. The checked-in manifest
  and `_VariableBudgetDetail` retain the superseded compact values.
- **Why the visual tests passed:** `spendee_balance_visual_spec_test.dart`
  only asserts the manually copied manifest constants; the dashboard test only
  checks outer shell coordinates; and the card test mounts an individual card
  on a different `#F8FAFC` Scaffold. None reads the final HTML cascade or
  compares a full production-theme dashboard frame to an approved screenshot.
  These tests validated a self-consistent approximation, not the source of
  truth.
