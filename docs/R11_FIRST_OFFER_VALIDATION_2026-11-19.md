## Implemented boundary and architecture

The existing service and controller retain eligibility and privacy authority; the existing accessibility window owns the root. Main creates and validates the exact child, grant and positive lease. The Worker retains slot and fence ownership; the three-slot limit and steady submission/release rules are unchanged. One revocable immutable-lifetime token accepts one exact READY use. A normal Main notification and the tail of successful child/grant installation call the same once-only consumer. Hide, route/lifetime/privacy/size replacement, detach and disposal revoke waiting work, including when there is no child. Detached lease 0 remains on its separate preparation/discard path. The first direct submission's worker acknowledgement precedes later retirement, while bootstrap retirement stays qualified by the exact current commit. The controller treats same-visual privacy changes as fresh lifetimes. The bounded capture binds event data to original show/capture owner, keeps compact first-use and actual withdrawal evidence, and measures first two per-slot shader preparation scopes without changing preparation policy.

`KeyguardOrbFirstOffer` is purpose-specific ownership transfer, not a second surface, release authority, scheduler, or generic grant registry: the existing steady target and pressure claim do not carry a producer fence or provide the same revocation semantics. The already large renderer, material controller, and capture reducer remain the existing ownership boundaries; a general split was not introduced under this explicitly scoped handoff. The new host fixture has fixed baseline/candidate identities and continues the existing R09/R10 focused orchestration; it does not add runtime policy.

This implements the reviewer-selected H1, not a finding that H1 caused all observed phone latency. Root inspection/dispatch (H2), successor shader or scheduling costs (H3), old-use capacity (H4), and actual removal/composition (H5) remain separate evidence questions. Physical pixels, physical wake/unlock, and physical removal are not timestamps available from these app records.
